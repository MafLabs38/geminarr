# Review decisions of pull request #38

One account signed in is one machine of notes. First round of the four agents on `996beaa`.

## R-38-1 | architecture | major | fixed

- **Finding**: Nothing moves the existing single-account data into a workspace (conversations, outbox, destination, old key).
- **Where**: Accounts.Database, KeyStore, Schema step 5
- **Reason**: The reviewer's second way: stated, not coded. Nothing was released with data in it (the first deployment was never signed in; the sandbox is throw-away), so no move was written. ADR 0026 (consequences) and the runbook say that a data folder from before accounts is not adopted and the first account is paired as a machine of its own.

## R-38-2 | architecture | major | fixed

- **Finding**: A key given by the deployment is shared by every account, and the spec, the ADR and the configuration disagree.
- **Where**: KeyStore, LinkService, SPEC §8.2, configuration.md, runbook
- **Reason**: Real. The key of the deployment now serves the one account that exists (the first workspace) and a second account is not linked to it (a line in the log says why); forgetting the first one serves the second. Tested (`KeyFileAccountsFixture`); SPEC, ADR 0026, configuration and runbook say the same.

## R-38-3 | architecture | major | fixed

- **Finding**: ADR 0004 was edited in place to reverse its decision, against the register's own rule.
- **Where**: docs/adr/0004, 0026, README
- **Reason**: Real. ADR 0027 (any account, no import) supersedes it; ADR 0004 has its text back with a status line; D-34, D-09 and D-10 point to 0027, and CLAUDE.md, SECURITY.md and VISION.md too.

## R-38-4 | architecture | minor | fixed

- **Finding**: SPEC §7.3 still said that the label of the account is never sent to Mnemarr; the machine name carries the part before the `@`.
- **Where**: docs/SPEC.md §7.3, AccountIdentity, ExtensionInbox
- **Reason**: Real. §7.3 and the two comments name what leaves: the part before the `@`, as the machine name.

## R-38-5 | architecture | minor | fixed

- **Finding**: The spec says that nobody signed in means no active account; the code keeps the last one after an expiry.
- **Where**: SPEC §8.1, ADR 0026
- **Reason**: Real. §8.1 and the ADR say it: the last account until *Disconnect*, and none for a session whose account cannot be named.

## R-38-6 | architecture | minor | declined

- **Finding**: The services build concrete stores themselves and `MachinesOfOtherAccounts` opens every workspace at each `Status()`.
- **Where**: AccountService, LinkService
- **Reason**: Cosmetic for now: a few small databases, once per request of an operator; the key path is now behind `IKeyStore.ExistsFor`. A factory on `IAccountWorkspaces` and a cache would be code for a cost nobody has.

## R-38-7 | architecture | minor | declined

- **Where**: ConversationsController
- **Reason**: Thin enough (one branch), and tested through the API; moving it adds a method that only that controller calls.

## R-38-8 | architecture | minor | declined
