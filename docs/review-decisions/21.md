# Review decisions of pull request #21

The answers to the findings of the four review agents on the head commit `33f8b93`. See the [README](README.md).

## R-21-1 | architecture | major | fixed

- **Finding**: The server works out why a logo is not used, but nothing in the interface shows it; the docs promise that the Settings page says so.
- **Where**: frontend/src/Settings/Settings.tsx, docs/configuration.md
- **Reason**: Real. The Settings page now shows an alert with the reason (never a path) when the picture of the menu is not used, with a test for both cases.

## R-21-2 | security | low | fixed

- **Finding**: The SVG check looked only at `href` and `style`: a `url(...)` in a presentation attribute (`fill`) was not checked, and several branches had no test.
- **Where**: src/Geminarr.Core/Identity/IdentityRules.cs
- **Reason**: Every attribute value is now checked for a `url()` that is not a fragment of the document and for an `@import`; tests for a presentation attribute, quotes and spaces in `url( )`, an upper-case handler, `javascript:` and `data:text/html` in other attributes, CDATA in a style and a file with no element. The image is served with `default-src 'none'; sandbox` anyway.

## R-21-3 | security | low | fixed

- **Finding**: `[KeepsItsOwnHeaders]` removes the application policy and the no-cache of any 200 or 304 of the endpoint that carries it, even if it did not say its own policy.
- **Where**: src/Geminarr.Host/Http/SecurityHeaders.cs
- **Reason**: The host keeps the answer's own headers only if it did say a Content-Security-Policy; the local is renamed after the mechanism.

## R-21-4 | quality | minor | fixed

- **Finding**: `Load` is a function that always returns held bytes (a dead branch), and the `If-None-Match` handling is written by hand next to what `File()` already does.
- **Where**: IdentityService, IdentityController
- **Reason**: The logo holds its bytes; `File()` answers the conditional requests, with an integration test for a matching ETag and for `*`, with and without the hash in the address.

## R-21-5 | architecture | minor | fixed

- **Finding**: F-SYS-04 is "1b" and the roadmap has no such row; a test uses the maintainer's own laboratory name.
- **Where**: docs/ROADMAP.md, IdentityRulesFixture
- **Reason**: The roadmap has the row; the test uses "Example Lab".

## R-21-6 | test | minor | fixed

- **Finding**: Boundaries and duplicates: a name of exactly 40 characters (and padded with spaces: the validator checked it untrimmed), the length of a WebP header, a third host that repeated a unit test, a fixed path in a factory, header assertions in the end-to-end test that repeat the integration test, an export used in one file.
- **Where**: BrandingOptionsValidatorFixture, IdentityRulesFixture, IdentityFixture, GeminarrFactory, smoke.spec.ts, identityColor.ts
- **Reason**: The validator trims like the service; the boundaries are tested; the duplicate test and its factory are deleted; the end-to-end test keeps what only it can show (the real image loads) and the 401 without a session.

## R-21-7 | quality | minor | declined

- **Finding**: The name is the `alt` of the image, the `title` of the badge and visible text; raw sizes in the CSS; the token list is duplicated between the server and the interface; the PNG bytes of the tests are defined twice; nine rows for two branches of the color test; no test that a new hash tries the image again.
- **Where**: IdentityBadge, IdentityBadge.module.css, identityColor, tests
- **Reason**: The badge, its CSS and its texts are deliberate copies of Mnemarr's and Portarr's (the maintainer wants the same design in the three products, ADR 0013); the lists are short and shared by convention; the rest is cosmetic.
