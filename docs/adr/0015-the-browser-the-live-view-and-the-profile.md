# 0015 — The browser, the live view and the profile

- **Status**: accepted
- **Date**: 2026-11-13
- **Spec**: D-23, F-CON-01 to F-CON-04, F-LGN; applies ADR 0004 (a dedicated account) and D-08 (read-only, on the assistant's own pages)

## Context

The session is the crown jewel (ADR 0004): the signed-in browser profile of a dedicated Google account. Nothing but the operator may reach it, the browser must load nothing but the assistant, and the operator has to sign in once in a place that is not their own browser. Vertical 3 builds that place and the state machine around it, before the reader that will use the session (vertical 4) and before the first spike has said how Gemini is read: so it knows the **session** and nothing else.

## Decision

1. **One Chromium, driven by Playwright, on a profile folder of its own** (`GEMINARR__BROWSER__PROFILEFOLDER`, `/profile`, a volume, mode `0700`, owned by the container's user). It runs without a window (the headless shell), with no sync, no extension and no saved password, and it does one thing at a time: a live view holds it, and a check of the session never shares it. The code that drives it is its own project (`Geminarr.Browser`) and is thin; **every decision is in Core** (the policy of origins, the parser of input, the rules of the live view, the state machine) and is tested without a browser.
2. **A route filter refuses every origin the policy does not allow** (D-08): the assistant's own host and the hosts its page loads its files from (`GEMINARR__BROWSER__ALLOWEDHOSTS`, which the first spike will write down), and the account provider's sign-in pages **only during a live view**. When the browser is only checking, a redirect to a sign-in page is recorded and the page is not loaded: the redirect is what says the session is gone. Plain http is for a sandbox or a test that says so.
3. **The live view is the browser's own screencast on a canvas** (SPEC §7.3): the page asks for it with an authenticated call that answers a single-use token, then opens a WebSocket on the same origin that presents it. The server checks the session of the operator, the `Origin` (a WebSocket is not bound by the same-origin policy), the token (used up by the first attempt, right or wrong, and void after a minute), and refuses a second viewer; it lasts at most ten minutes. What the page sends back (mouse, keys, a paste) is JSON, bounded and checked again by the server (coordinates inside the screen, a key that is a key, a text that is not endless) before it reaches the browser. **Nothing that is shown or typed is logged or kept**: pictures go from the browser to the socket, and the page keeps no text.
4. **The end of a sign-in is said by the operator, and checked against the page the browser is on** (`GEMINARR__BROWSER__SIGNINDETECTION=Confirm`, the default): a button of the live view says "I am signed in", and the server accepts it only if the browser is on the assistant's own page. The address alone does not decide, because an assistant may show its page to somebody who is not signed in (Gemini has a guest mode, which the first real try showed within seconds). `Page` decides from the address alone, for an assistant that sends everybody who is not signed in to a sign-in page, and for the tests. Either way the state becomes `connected`, the profile is marked as holding a session, the live view closes and the browser closes. A session that was never made is `not-connected`; a session that is gone is `needs-login` after `Reader:LoginFailures` passes in a row that were sent to a sign-in page (a network error is never "signed out").
5. **The state machine is one place** (`ConnectionTracker`, with the service that the API uses): `not-connected`, `connecting` (a live view is open: nothing is read), `connected`, `degraded`, `needs-login`, `paused` (until a moment or until resumed). A live view that nobody opened and a pause whose moment has come end by themselves where the state is read. **Disconnect destroys the content of the profile** (the folder stays: it is a mount point).
6. **The reader `Web` knows the session and reads nothing yet**: a pass checks the session with the profile, lists no conversation, and keeps the connection and the heartbeat alive; the conversations come with the next vertical, behind the same port.
7. **The image is Ubuntu, not chiseled, from this vertical**: Chromium needs its system libraries, installed in the last stage by Playwright's own driver, for the architecture of the image. The multi-architecture build therefore runs that stage under QEMU (the `image` job installs it), and the end-to-end test runs the amd64 image against a fake assistant on its own host (a synthetic page that needs a sign-in), which walks the whole live view with a real browser.
8. **Chromium runs without its own sandbox by default** (`GEMINARR__BROWSER__CHROMIUMSANDBOX=false`, which is Playwright's own default and makes it start with `--no-sandbox`): the sandbox needs user namespaces or a seccomp profile that a hardened container (no capability, the platform's default profile, no privilege escalation) does not give, and the browser then does not start. The cost is real: a flaw in the browser's renderer would run as the container's user, which can read the profile and the data folder. What holds instead: the pages that can be loaded are the assistant's and a few hosts of files (a page is **navigated to** only if it is the assistant's, or a sign-in page during a live view; WebSockets follow the same rule), the browser reads nothing but the assistant, the account is a **dedicated** one (ADR 0004) whose damage is bounded, the container is non-root with no capability and a read-only root, and the network policy repeats the list. Where the platform allows the sandbox (user namespaces enabled, or a seccomp profile that permits them), the setting turns it on. This is the browser's privilege model, so it is the maintainer's to accept (CLAUDE.md, rule 12).

## Alternatives considered

- **A remote desktop (VNC, noVNC) in the container**: rejected, a second server with its own authentication and a wider surface; the screencast of the browser itself is enough and goes through Geminarr's own checks.
- **Sign in on the operator's own browser and copy the cookies**: rejected (ADR 0004): the operator's browser holds their other sessions, and a cookie that is pasted is a secret that passes through too many places.
- **The browser as another container**: rejected for now, one more thing to deploy and to keep private; the browser project is behind a port, so it can move.

## Consequences

- The image is larger (about 1 GB). A browser upgrade is an image version, with a line in the runbook.
- The first spike (S1) needs this vertical's live view: the operator signs in to the dedicated account once, and the spike measures what the page gives.
- A pass that checks the session with a profile tells "signed out" only by a redirect to a sign-in page, which a guest-mode assistant never sends: **what "signed in" looks like on the real page (a mark of the account in the page) is measured by the first spike**, and until then an expired session on such an assistant is not seen by this check. The exact hosts that the assistant's page needs are measured by the spike: the defaults are a guess that the policy refuses to widen silently.
- A smoke test of the pushed arm64 image remains a precondition of the release that carries the browser ([releasing.md](../releasing.md)).
